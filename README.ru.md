# 🌿 PlantDiseases

**Определение болезней комнатных и садовых декоративных растений с помощью ИИ — камера на устройстве, облачный инференс, двуязычные планы ухода.**

[![CI](https://github.com/pmixay/plantdiseases/actions/workflows/ci.yml/badge.svg)](https://github.com/pmixay/plantdiseases/actions/workflows/ci.yml)

Двухэтапный ML-конвейер (детектор листьев YOLOv8 → классификатор на
замороженном backbone DINOv2 ViT-S/14 + LoRA + MLP-голова), развёрнутый за
защищённым FastAPI-сервисом, в паре с Android-клиентом на Kotlin, который
включает историю сканирований, напоминания об уходе за растениями и
ИИ-фитопатолога.

### 🌐 [**Открыть сайт проекта →**](https://pdis.arbuz.lol/)

Интерактивная двуязычная (RU / EN) витрина возможностей приложения,
ML-конвейера и живых графиков с метриками.

## Что это умеет

| | |
|---|---|
| 📷 | **Сфотографируй лист — получи диагноз** — классификатор на 9 классов, включая настоящую голову-отказ `not_a_plant`, плюс фильтр размытия, чтобы нечёткие кадры не получали ложную уверенность. |
| 📴 | **Офлайн-сканирование (Aqua)** — выберите модель `aqua` на экране сканирования для полностью офлайн-диагноза (TFLite, без обращения к серверу); модель скачивается с сервера и кешируется. |
| 🌍 | **Двуязычные планы ухода** — каждый диагноз сопровождается описанием на EN + RU, чек-листом лечения, советами по профилактике, графиком полива / подкормки / влажности и списком тревожных признаков. |
| 🪴 | **Личный сад** — история сканирований на базе Room, отслеживание нескольких растений, напоминания о поливе / подкормке через WorkManager. |
| 🤖 | **ИИ-фитопатолог** — опциональный чат через OpenRouter, привязанный к диагнозу вашего сканирования, для уточняющих вопросов. |
| 🔎 | **Определение вида** — интеграция с PlantNet (опционально) автоматически заполняет вид растения по фото. |
| 📊 | **Честная неопределённость** — топ-3 альтернативы, конформные предсказательные множества, перенаправление слабого «здорового», оценка тяжести + мягкие предупреждения (`uncertain_healthy`, `low_confidence`, `blurry_image`). |

## Архитектура

```
┌──────────────────────┐         ┌──────────────────────────────────┐
│   Android (Kotlin)   │  HTTP   │   Python-сервер (FastAPI)        │
│                      │ ──────► │                                  │
│  • Съёмка CameraX    │         │   ┌──────────────────────────┐   │
│  • История (Room)    │         │   │ Этап 1 — детектор листа  │   │
│  • Ktor + OkHttp     │  JSON   │   │ YOLOv8n один класс        │   │
│  • UI на Material 3  │ ◄────── │   └──────────┬───────────────┘   │
│  • Строки EN / RU    │         │              │                   │
│  • Воркер напоминаний│         │   ┌──────────▼───────────────┐   │
│  • Профиль + статы   │         │   │ Этап 2 — классификатор   │   │
│                      │         │   │ замороженный DINOv2 ViT-S/14 │
│                      │         │   │ + LoRA + MLP-голова       │   │
│                      │         │   │ 9 классов, вкл. NaP-голову│   │
│                      │         │   │ + OOD-фильтр (эмбеддинг-kNN)│ │
│                      │         │   │ + фильтр размытия (Лаплас)│   │
│                      │         │   └──────────────────────────┘   │
└──────────────────────┘         └──────────────────────────────────┘
```

Почему два этапа — сначала YOLOv8n находит лист, поэтому классификатор
видит плотный кроп вместо всей комнаты. OOD-фильтр с логическим «И»
([`pipeline.py`](server/pipeline.py)) ловит остаточный случай, когда этап 1
слабо срабатывает на текстуре, не являющейся листом: он срабатывает, только
когда совпадают и уверенность детектора, и OOD-сигнал со стороны
классификатора. Этот сигнал — расстояние k-NN в пространстве эмбеддингов по
CLS-вектору DINOv2 ([`ood.py`](server/ood.py)), когда в комплекте есть банк
эмбеддингов; иначе используется устаревший порог MaxLogit. Фильтр размытия
(дисперсия лапласиана) сразу отправляет нечёткие кадры в вердикт
`not_a_plant`, чтобы пользователь переснял, а не получил ложный диагноз.

Подробный рецепт обучения — в
[`server/train_notebook.ipynb`](server/train_notebook.ipynb) и
[`MODEL_CARD.md`](server/models/MODEL_CARD.md).

**Семейства моделей.** Три уровня мощности (объявлены в
`classes.json -> model_family`, отдаются через `/api/capabilities`; клиент
выбирает одно на каждое сканирование, а `/api/capabilities` сообщает,
какие из них предлагает сервер):

| Семейство | Backbone | Вход | Где работает |
|---|---|---|---|
| `aqua` | MobileNetV3-Small (дистиллирована из `gamma`) → TFLite INT8 | 224 | **на устройстве, полностью офлайн** (скачивается с сервера, кешируется) |
| **`gamma`** | **замороженный DINOv2 ViT-S/14 + MLP-голова** | **224** | **сервер — текущий прод, баланс цены/точности** |
| `frontier` | замороженный DINOv2 ViT-B/14 (~86M) + MLP-голова | 224 | сервер — высокая мощность; **инференс по умолчанию ВЫКЛ** (нужен GPU-хост), приложение показывает «недоступно», пока не включено |

`gamma` и `frontier` используют один рецепт на замороженном DINOv2
(различаются только backbone и размер входа); `aqua` — мобильный
ученик на основе дистилляции знаний (`train_notebook.ipynb` §5),
экспортированный в TFLite.

> **Опциональное дополнение данных:** §2 может подтянуть реальные наборы
> по болезням комнатных / декоративных растений с Kaggle (в т.ч. снимки
> болезней money-plant / потоса). Это **мягкий отказ** — укажите учётные
> данные для включения, иначе ноутбук аккуратно пропустит этот шаг.
> Учётные данные могут быть **токеном API нового формата** (секрет Colab
> или переменная окружения `KAGGLE_API_TOKEN`, либо
> `~/.kaggle/access_token`) или устаревшим `kaggle.json`; хелпер §1
> `kaggle_install_api_config()` позволяет загрузить любой из этих файлов
> в Colab. Источник используется **только для обучения** и отбрасывает
> любую папку, которую не удаётся уверенно сопоставить, а прогон печатает
> каждую найденную папку, чтобы вы могли уточнить карту меток.

## Классы

Голова классификатора — это **9 обучаемых классов** (по алфавиту,
совпадает с `sorted(ImageFolder.classes)`). `leaf_spot` объединяет
бактериальную и грибковую пятнистость листьев, а `pests` объединяет
червецов и щитовок — в каждом случае по фото с телефона их надёжно не
различить:

| # | Класс | Название EN | Название RU |
|---|-------|---------|---------|
| 0 | `gray_mold_botrytis`         | Gray Mold (Botrytis)          | Серая гниль (ботритис)    |
| 1 | `healthy`                    | Healthy Plant                 | Здоровое растение         |
| 2 | `leaf_scorch_underwatering`  | Leaf Scorch (Under-watering)  | Краевой ожог (недолив)    |
| 3 | `leaf_spot`                  | Leaf Spot (fungal + bacterial)| Пятнистость листьев       |
| 4 | `not_a_plant`                | Not a Plant                   | Не растение               |
| 5 | `nutrient_deficiency`        | Nutrient Deficiency           | Дефицит питания           |
| 6 | `pests`                      | Sap-sucking Pests (mealybug + scale) | Сосущие вредители (червецы + щитовки) |
| 7 | `powdery_mildew`             | Powdery Mildew                | Мучнистая роса            |
| 8 | `viral_disease`              | Viral Disease                 | Вирусное заболевание      |

Конвейер также принимает **отложенные** метки на `/api/feedback`
(`edema`, `sunburn_or_scorch`), хотя голова классификатора их пока не
предсказывает — цикл дообучения использует их, чтобы приоритизировать
следующий раунд сбора данных.

Канонический список: [`server/models/classes.json`](server/models/classes.json).

## Быстрый старт

### Сервер

**Linux / macOS:**
```bash
cd server
chmod +x start.sh
./start.sh
```

**Windows:**
```cmd
cd server
start.bat
```

Скрипт создаёт виртуальное окружение, ставит PyTorch только для CPU +
`requirements.txt` и запускает FastAPI на `http://localhost:8000`.

Веса модели **не коммитятся** и **не скачиваются автоматически** — сначала
положите обученный набор (`detector.{pt,onnx}`, `classifier.onnx`,
`classes.json`, JSON калибровки) в `server/models/`; без него сервер **падает
сразу**, а `train_notebook.ipynb` §6b упакует их в архив. Продакшен-настройка
(systemd, nginx/TLS, API-ключи, подпись Android/FCM) — в
[`DEPLOYMENT.md`](DEPLOYMENT.md).

### Android-клиент

1. Откройте `android/` в Android Studio (Hedgehog 2023.1+), синхронизируйте
   Gradle, запустите на устройстве/эмуляторе.
2. URL сервера зашивается через `BuildConfig.API_BASE_URL`; переопределите при
   сборке: `./gradlew :app:assembleDebug -PAPI_BASE_URL=http://192.168.1.42:8000/`.

Подпись релиза, push (FCM), TLS и опциональные интеграции — `PLANTNET_API_KEY`
(определение вида) и `OPENROUTER_API_KEY` (ИИ-фитопатолог); без них сервер
работает и сообщает «недоступно» — описаны в [`DEPLOYMENT.md`](DEPLOYMENT.md).

## API

| Метод | Путь | Описание |
|---|---|---|
| `GET`  | `/api/health`              | Проверка живости + аптайм + число классов |
| `GET`  | `/api/capabilities`        | Доступность по семействам (aqua / gamma / frontier) **плюс** версия сервера, версия и архитектура модели, двуязычные метаданные классов (объединяет прежние `/api/version` и `/api/classes`) |
| `GET`  | `/api/metrics`             | JSON-счётчики (запросы, ошибки, задержка, точность по классам из обратной связи) |
| `GET`  | `/api/metrics/prometheus`  | Текстовая экспозиция Prometheus (v0.0.4) |
| `POST` | `/api/analyze`             | Загрузка изображения → двуязычный диагноз (`?family=aqua\|gamma\|frontier`, по умолчанию `gamma`) |
| `GET`  | `/api/guide/photo/{key}` | Примеры фото болезней/вредителей (отдаёт сервер, кешируется приложением) |
| `GET`  | `/api/aqua/manifest` · `/api/aqua/model` | Манифест + байты офлайн-модели Aqua TFLite (приложение скачивает/обновляет её) |
| `POST` | `/api/identify`            | Определение вида через PlantNet (корректно при отсутствии настройки) |
| `POST` | `/api/chat`                | ИИ-фитопатолог (OpenRouter; корректно при отсутствии настройки) |
| `POST` | `/api/care-plan`           | График полива / света / влажности / подкормки + чек-лист лечения |
| `POST` | `/api/progression`         | Сравнение сканирований → вердикт тренда + спарклайн тяжести на 5 точек |
| `POST` | `/api/feedback`            | Был ли диагноз верным? Append-only сигнал для обучения |

Формы ответов и правила валидации задокументированы прямо в коде
[`server/main.py`](server/main.py).
