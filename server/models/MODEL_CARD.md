# PlantVision — Model Card

> **Per-run provenance lives in `model_card.json` alongside the trained
> artefacts**, not here. Class counts, calibration (`temperature`,
> `conformal`), INT8 drift + paired-bootstrap CI, and per-class recall
> bootstrap CIs are regenerated by `train_notebook.ipynb` §6 on every
> run and shipped with the model files you drop into `server/models/`
> (the server does not auto-download them). This file is a stable,
> version-agnostic overview and carries **no run-specific numbers** by
> design.
>
> `model_card.json` also carries a `benchmark` block (notebook §6): batch-1
> inference latency (p50/p95/mean ms) + on-disk size for the shipped
> classifier ONNX and — on an `aqua` run — the on-device TFLite student.
> `cpu_1thread` is the canonical cross-tier number (single-core server
> budget) and includes hflip-TTA when enabled; a `cuda` timing is added when
> a GPU provider is present (the `frontier` tier serves on GPU).
>
> §6b packs one **per-training-mode** archive,
> `models/plantvision_<family>_v<version>.tar` (e.g. `…_aqua_…`,
> `…_gamma_…`, `…_frontier_…`). Server drop-in artefacts (ONNX, `classes.json`,
> `temperature.json`, `conformal.json`, `ood_embedding.npz`) sit at the archive
> **root**; analysis/research artefacts (`model_card.json` incl. benchmarks,
> `training_metrics.json`, `run_log.jsonl`) ride along; and the on-device
> `aqua/` subdir (`aqua_classifier.tflite` + its `classes.json`) is included
> when an `aqua` run produced it. Heavy torch checkpoints are intentionally
> excluded (runtime is ONNX/TFLite-only).

## Pipeline

Two stages (`server/pipeline.py`):

1. **Stage 1 — YOLOv8n** single-class `plant_leaf` detector, indoor-trained,
   localises the leaf so Stage 2 sees a tight crop, not a whole room.
2. **Stage 2 — classifier** on the crop at the `classes.json` `img_size`.
   The "is it diseased / which disease" decision is 100 % Stage 2.

Runtime guards: blur gate (variance-of-Laplacian), an OOD AND-gate
(detector confidence **and** a classifier-side OOD signal — embedding
k-NN distance where a bank is shipped, else the legacy MaxLogit floor),
**whole-image-vs-crop arbitration** (the full frame is folded into the
mean vote to recover the detector-crop loss on leaf-centric inputs),
weak-healthy reroute, temperature scaling, and RAPS conformal prediction
sets.

## Model families (Aqua / Gamma / Frontier)

The bundle declares its capacity tier in `classes.json -> model_family`,
surfaced by `/api/version`. Three tiers share one training/eval/export
recipe (`train_notebook.ipynb`, selected by `MODEL_FAMILY` in §1):

| Family | Backbone | Input | Role |
|---|---|---|---|
| `aqua` | MobileNetV3-Small (distilled from `gamma`) → TFLite INT8 | 224 | **on-device, fully offline** (app downloads + caches the model) |
| **`gamma`** | **frozen DINOv2 ViT-S/14 + MLP head** | **224** | **current production tier — balance of cost/accuracy** |
| `frontier` | frozen DINOv2 ViT-B/14 (~86M) + MLP head | 224 | high-capacity (GPU); **server inference gated OFF by default** |

`gamma` and `frontier` share one frozen-DINOv2 + MLP-head recipe (only the
backbone + input size differ). `aqua` is a separate knowledge-distilled mobile
student (notebook §5) — the DINOv2 `gamma` model is its teacher. Bundles trained
before the `model_family` field existed report `model_family = "gamma"`.

## Classifier architecture

The production artefact is an ONNX graph and the runtime is
**architecture-neutral** — it serves whatever backbone+head the shipped
bundle declares (`classes.json -> architecture`):

- **v2.6.7 (shipped, `gamma`; trained on dataset supplement v5):** same recipe as
  v2.6.5/v2.6.6. **Two structural changes landed.** (1) The *agricultural* Kaggle
  strawberry Botrytis proxy was **removed entirely**; `gray_mold_botrytis` now trains
  on clean foliage only (iNat 606 + supplement 255 + DoctorP 96 → 339 train) and is
  **fixed**: `val_realworld` recall/precision **0.83/0.83**, and **0.913 recall on the
  new stable held-out test slice** — it had been the binding class for five versions.
  (2) A **stable, class-aware, group-aware test split** (`make_test_split`, §2) carves
  a content-hash held-out slice that is reproducible across dataset versions; it is
  graded as `final test` in §6. Headline `val_realworld` (n=1854): disease macro-F1
  **0.862** (int8) / 0.868 (fp32), overall accuracy **91.1%**, healthy-bias 0.95;
  **stable test** (n=2329): disease macro-F1 **0.866**. **Ships INT8**
  (`classifier_int8.onnx`, 22.5 MB → 130 MB bundle): INT8 is statistically tied with
  FP32 (paired-bootstrap int8−fp32 CI [−0.018, +0.005], n.s.). Calibration re-fit on
  the **int8** path (no fp32 fallback): T=0.761, RAPS α=0.2 → coverage 0.991, mean set
  size 1.90. OOD now uses the **embedding k-NN gate** (threshold 0.606, NaP recall
  0.942 @ 5% plant FPR); the legacy MaxLogit floor auto-disabled (not_a_plant is now a
  strong enough trained class that its MaxLogit overlaps real plants). aqua student
  recovered after the §5 feature-distillation fix (KD val-macroF1 0.780→**0.798**).
  Detector mAP50 **0.819**. **Remaining weakness (v6 target):** the two physiological
  classes *over-predict* — `nutrient_deficiency` precision **0.679** (recall 0.878) and
  `leaf_scorch_underwatering` precision **0.745** (recall 0.814); they alone hold
  macro-F1 at 0.86. Rows are agent-judged, so the gate is a **proxy** until verified
  production volume exists.
- **v2.6.6 (`gamma`; trained on dataset supplement v4 — superseded by v2.6.7, never shipped):**
  same recipe as v2.6.5, retrained on **eval-supplement v4** (1951 rows: nutrient
  disambiguating negatives + the first offline-judged production scans) with the
  train-source de-crop landed (rice `kaggle_nutrient` + CoLeaf removed, COCO
  not_a_plant trimmed). `val_realworld` (n=2150): disease macro-F1 **0.861** (flat
  vs v2.6.5, within noise). **INT8 reclaimed** — this run's INT8 *beat* FP32
  (+0.0057, paired-bootstrap CI [−0.003, +0.014], n.s.), so it ships
  `classifier_int8.onnx` (22.5 MB) → 130 MB bundle, recovering the 4× size win.
  Mixed weak-class result: powdery P **0.875→0.939**, gray_mold precision
  **0.840→0.888**, but **leaf_scorch regressed** (F1 0.805→0.719 — v4's generic
  healthy negatives over-corrected) and viral precision dipped (0.954→0.814,
  eval-slice-confounded). Calibration: T=0.843, RAPS α=0.2 → coverage 0.984, set
  size 1.89. **Aqua student regressed** (KD val-macroF1 0.838→0.780; on hard real
  web photos it collapses toward healthy/not_a_plant — see the integrity probe).
  **Caveats:** the exported artifact's `classes.json` still reads `model_version
  2.6.5` (the version constant was bumped to 2.6.6 *after* this export — re-export
  before shipping), and ship is pending the leaf_scorch fix (v5).
- **v2.6.5 (`gamma`; trained on dataset supplement v3):** same recipe
  as v2.6.x, retrained on **eval-supplement v3** (1825 rows: hard houseplant-
  domain gate, boundary hard-negatives for the over-triggering classes, gray_mold
  backfill 120→228 — see `docs/DATASET_LABELING_PLAN.md`). Headline `val_realworld`
  (n=2334): disease macro-F1 **0.865**, overall accuracy **91.9%**, healthy-bias
  0.97. The v3 precision-hardening landed: **leaf_scorch precision 0.71→0.774**
  (over-trigger 1.21×→1.08×), gray_mold eval n 71→91 (tighter CIs). **Shipped
  FP32** (`classifier.onnx`, 87.3 MB): INT8 was *significantly* worse this run
  (paired-bootstrap CI [−0.025, −0.004] excludes 0), so the export gated back to
  FP32 — the server has the CPU headroom. Calibration re-fit: T=0.727, RAPS α=0.2
  → coverage 0.981, mean set size 1.84. The aqua on-device student distilled to
  **1.71 MB** TFLite (≈17 ms/img CPU single-thread; gamma ONNX ≈299 ms with TTA —
  both in `model_card.json -> benchmark`). Rows remain agent-judged
  (`verified_by=agent_vision`), so the gate is a **proxy** until verified
  production volume exists.
- **v2.6.x (`gamma`):** same recipe as v2.5 (below) plus the
  **in-domain Kaggle eval-supplement** (`maxayyt5/houseplant-disease-eval-supplement`,
  source `supplement`) wired into `train_notebook.ipynb` §2 as an
  **eval-eligible** source — a held-out fraction seeds `val_realworld` /
  `val_indomain` / the calibration splits, thickening the thin weak-class eval
  slices (esp. `nutrient_deficiency`, eval n≈25). The rows are agent-judged
  (`verified_by=agent_vision`), not human-verified, so the gate measured on them
  is a **proxy** until verified production volume exists (see
  `docs/DATASET_LABELING_PLAN.md`).
- **v2.5.x (`gamma`):** frozen **DINOv2 ViT-S/14** backbone +
  LoRA on the later blocks (rank 16 / last 8 blocks, unchanged since v2.4
  — the §3 probe showed the *features*, not the head, cap weak-class
  recall) + a small MLP head, **no distillation**. v2.5 ships **per-class
  precision CIs** beside the recall CIs (the physiological classes are
  precision-bound — they over-trigger). Motivated by a frozen DINOv2-S linear
  probe reaching ~0.91 top-1 on `val_realworld`. v2.4 rebuilds the §2
  data supply for the weak classes (new ornamental/houseplant disease
  source; black-background segmented-Aloe and outdoor-cactus-as-pests
  data removed; noisy generic-yellowing query dropped). v2.4 also adds
  **DoctorP** — real plant-doctor app photos — which supplies the
  starved `gray_mold_botrytis` / `pests` classes in their deployment
  framing and is **eval-eligible**, so `val_realworld` (the ship gate)
  now includes real gardener-view photos across the whole taxonomy
  instead of only PlantDoc field crops.
  Shipped FP32 (`PREFER_FP32`) — dynamic-INT8 drift on `val_realworld`
  was not statistically significant (paired bootstrap CI spans 0) and the
  single-core CPU budget has the latency headroom.
- **`aqua` (on-device):** a **MobileNetV3-Small** student
  **knowledge-distilled from the `gamma` DINOv2 teacher** (notebook §5),
  exported to **TFLite** (dynamic-range INT8, float I/O) and run in the app
  for fully-offline inference. KD is warranted here — the target is a hard
  on-device size/latency budget, so a tiny student is the deliverable, not a
  regression. This is distinct from the retired v2.2 KD chain below.
- **v2.2 (legacy, retired):** a MobileNetV3-Large student distilled from an
  EfficientNetV2-S teacher *as the server model*. Removed because distilling a
  weaker server model under a much stronger teacher under-performed the frozen
  DINOv2 backbone; the server runtime is **ONNX-only** (the PyTorch `.pth`
  fallback was removed).

## Classes

**9 trainable** (alphabetical, = `sorted(ImageFolder.classes)`):
`gray_mold_botrytis`, `healthy`, `leaf_scorch_underwatering`,
`leaf_spot` (merged bacterial + fungal — not reliably separable from a
phone photo), `not_a_plant`, `nutrient_deficiency`, `pests` (merged
mealybugs + scale), `powdery_mildew`, `viral_disease`. The canonical
list is `classes.json` shipped with the trained artefacts.

Content cards exist (no classifier head yet) for deferred conditions
`edema` and `sunburn_or_scorch`.

## Validation contract

| Slice | Role | Pass criterion |
|---|---|---|
| `val_indomain` | training-loop metric, early stopping | best head checkpoint restored |
| `val_realworld` | **primary ship/no-ship gate** | disease macro-F1 ≥ **0.70**; no disease class recall = 0; healthy-bias < 1.5; healthy recall ≥ 0.70 |
| `val_studio` (PlantVillage) | transfer / background-bias monitor | tracked, never blocking |
| `temperature_cal` | temperature scaling | held out |
| `conformal_cal` | RAPS calibration | held out; 80/20 fit/audit when n ≥ 200 |

PlantVillage is **excluded** from the real-world gate and from both
calibration splits — its studio backgrounds violate exchangeability with
the deployment distribution.

## Calibration & OOD

Temperature scaling (Guo et al. 2017) + inductive RAPS conformal
(Angelopoulos et al. 2021) are fit on the **shipped artefact's** logits
so calibration matches what is served. The conformal hyper-parameters
(`alpha`, `lambda_reg`, `k_reg`) are grid-searched on a held-out audit
split for the smallest set size that still clears the 0.90 coverage
target (RAPS otherwise over-covers on this sharp classifier).

**OOD** uses an **embedding-space k-NN distance** (Sun et al. 2022) on
the DINOv2 CLS vector — the classifier ONNX exports the embedding as a
second output, and a memory bank of in-distribution plant embeddings +
a threshold (calibrated at a target plant false-positive rate on a
disjoint split) ship in the bundle (`ood_embedding.npz` +
`classes.json → ood.embedding`). It is AND-gated with detector
confidence. This replaces **MaxLogit** (Hendrycks 2019), which goes dead
once the `not_a_plant` head is confident enough that plant/NAP MaxLogit
separation is non-positive; the MaxLogit floor remains as the fallback
when no embedding bank is shipped (`max_logit_floor`).

## Known limitations

- **Thin classes** (`gray_mold_botrytis`, `leaf_scorch_underwatering`,
  `nutrient_deficiency`) are supply-bound (tens–low-hundreds of
  in-domain images) with small eval slices, so their per-class recall
  CIs are wide — the bundle's `model_card.json` ships those CIs. More
  in-domain data, not a bigger backbone, is the ceiling here.
- `leaf_spot` is a coarse umbrella; no sub-class (fungal vs bacterial)
  accuracy is claimed.
- `viral_disease` is incurable; the pipeline escalates severity by one
  level on a high-confidence viral verdict.
- **`viral_disease` over-triggers on naturally variegated / vividly
  patterned ornamental foliage** (Calathea/Goeppertia, Maranta, Caladium,
  Coleus, Croton, Aglaonema, Begonia rex…): the classifier reads the
  natural mottling as viral *mosaic*. This is a training-data coverage gap,
  not a pipeline bug — iNaturalist research-grade healthy photos skew to
  plain-green specimens, so the strongly-patterned cultivars were
  under-represented as healthy negatives. **Data fix (applied):**
  `INAT_HEALTHY_TAXA` in `train_notebook.ipynb` was broadened with those
  genera so the next training run learns that patterning ≠ mosaic; a
  dedicated `natural_variegation` negative class is the longer-term option.
  **Runtime mitigation (shipped):** below `VIRAL_MIN_CONFIDENCE` (0.65) a
  viral verdict is demoted to low-confidence and always carries a
  "could be natural variegation" caveat (`server/pipeline.py`). The
  feedback corpus already records these as `predicted=viral_disease,
  corrected=healthy` with the image — mine them via
  `tools/analyse_feedback.py` (confusion matrix) for the retrain.
- The dataset mix leans agricultural (PlantDoc / PlantVillage); real
  houseplant recall rides on the iNaturalist supplement and first-party
  data.
