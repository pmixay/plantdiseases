# PlantVision — Model Card

> **Per-run provenance lives in `model_card.json` inside the fetched
> model bundle**, not here. Class counts, calibration (`temperature`,
> `conformal`), INT8 drift + paired-bootstrap CI, and per-class recall
> bootstrap CIs are regenerated by `train_notebook.ipynb` §6 on every
> run and shipped in the bundle the server downloads from
> `MODEL_BUNDLE_URL` (see `server/model_fetch.py`). This file is a
> stable, version-agnostic overview and carries **no run-specific
> numbers** by design.

## Pipeline

Two stages (`server/pipeline.py`):

1. **Stage 1 — YOLOv8n** single-class `plant_leaf` detector, indoor-trained,
   localises the leaf so Stage 2 sees a tight crop, not a whole room.
2. **Stage 2 — classifier** on the crop at the `classes.json` `img_size`.
   The "is it diseased / which disease" decision is 100 % Stage 2.

Runtime guards: blur gate (variance-of-Laplacian), an OOD AND-gate
(detector confidence **and** classifier MaxLogit, Hendrycks 2019),
weak-healthy reroute, temperature scaling, and RAPS conformal prediction
sets.

## Classifier architecture

The production artefact is an ONNX graph and the runtime is
**architecture-neutral** — it serves whatever backbone+head the shipped
bundle declares (`classes.json -> architecture`):

- **v2.2 (last shipped):** MobileNetV3-Large student distilled from an
  EfficientNetV2-S teacher.
- **v2.3 (target — `train_notebook.ipynb`):** frozen **DINOv2 ViT-S/14**
  backbone + LoRA on the later blocks + a small MLP head, **no
  distillation**. Motivated by a frozen DINOv2-S linear probe reaching
  ~0.91 top-1 on `val_realworld` — well above the distilled student.

## Classes

**8 trainable** (alphabetical, = `sorted(ImageFolder.classes)`):
`gray_mold_botrytis`, `healthy`, `leaf_scorch_underwatering`,
`leaf_spot` (merged bacterial + fungal — not reliably separable from a
phone photo), `not_a_plant`, `nutrient_deficiency`, `powdery_mildew`,
`viral_disease`. The canonical list is the bundle's `classes.json`.

Content cards exist (no classifier head yet) for deferred conditions
`edema`, `sunburn_or_scorch`, and the staged pest classes `mealybug` /
`scale` (head off by default — `INCLUDE_PEST_CLASSES` in
`train_notebook.ipynb` §1).

## Validation contract

| Slice | Role | Pass criterion |
|---|---|---|
| `val_indomain` | training-loop metric, early stopping | best head checkpoint restored |
| `val_realworld` | **primary ship/no-ship gate** | disease macro-F1 ≥ **0.70**; no disease class recall = 0; healthy-bias < 1.5; healthy recall ≥ 0.70 |
| `val_studio` (PlantVillage) | transfer / background-bias monitor | tracked, never blocking |
| `temperature_cal` | temperature scaling | held out |
| `conformal_cal` | RAPS calibration | held out; 80/20 fit/audit when n ≥ 200 |

PlantVillage is **excluded** from the real-world gate and from both
calibration splits — its studio backgrounds violate exchangeability with
the deployment distribution.

## Calibration & OOD

Temperature scaling (Guo et al. 2017) + inductive RAPS conformal
(Angelopoulos et al. 2021) are fit on the **shipped artefact's** logits
so calibration matches what is served. OOD uses **MaxLogit** (robust
under temperature scaling + label smoothing where MSP collapses),
AND-gated with detector confidence; it auto-disables
(`max_logit_floor: null`) when plant/NAP separation is non-positive.

## Known limitations

- **Thin classes** (`gray_mold_botrytis`, `leaf_scorch_underwatering`,
  `nutrient_deficiency`) are supply-bound (tens–low-hundreds of
  in-domain images) with small eval slices, so their per-class recall
  CIs are wide — the bundle's `model_card.json` ships those CIs. More
  in-domain data, not a bigger backbone, is the ceiling here.
- `leaf_spot` is a coarse umbrella; no sub-class (fungal vs bacterial)
  accuracy is claimed.
- `viral_disease` is incurable; the pipeline escalates severity by one
  level on a high-confidence viral verdict.
- The dataset mix leans agricultural (PlantDoc / PlantVillage); real
  houseplant recall rides on the iNaturalist supplement and first-party
  data.
